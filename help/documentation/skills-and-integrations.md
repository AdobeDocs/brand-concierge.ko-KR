# 기술 및 통합 프레임워크 {#skills-and-integrations}

통합(이전의 도구)은 데이터 소스 또는 백엔드에 대한 연결입니다. 스킬은 행동이다.

하나의 통합은 여러 스킬에서 사용할 수 있습니다. 한 스킬이 여러 가지 통합을 사용할 수 있습니다. 이러한 구성 요소를 독립적으로 구성하고 함께 매핑합니다.

## 기술

기술은 컨시어지의 행동 계층이다. 컨시어지가 수행할 수 있는 단일 작업(처리, 절차, 응답 방식)을 정의하는 재사용 가능한(named, reservable) 단위입니다. 스킬은 자신의 데이터를 보유하지 않으며, 스킬에 첨부된 통합에서 기능을 차용합니다.

모든 스킬은 다섯 부분으로 구성됩니다.

| 부분 | 정의 |
| --- | --- |
| 이름 | 스킬 식별자 |
| 설명 | 그 기술이 무엇에 쓰이는지, 그 목적은 평이한 말로. |
| 다음의 경우에 사용 | 트리거 조건입니다. 다른 스킬이 아닌 이 스킬을 언제 호출해야 하는지를 컨시어지에 알려주는 라우팅 신호입니다 |
| 통합 | 이 스킬이 작업을 수행하기 위해 호출할 수 있는 특정 도구입니다. 스킬은 여기에 첨부된 항목만 사용할 수 있습니다. |
| 명령 파일 | 스킬의 작동 방식과 요청을 해석하고 응답 형식을 지정하며 가드레일을 적용하는 방법을 제어하는 세부 지침입니다 |

런타임 시 스킬이 작동하는 방식: 사용자 메시지가 도착하면 플랫폼은 각 활성 스킬의 &quot;사용 시기&quot; 트리거에 대해 해당 스킬을 일치시키고 일치하는 스킬에 메시지를 라우팅합니다. 그런 다음 해당 스킬이 지침을 실행하고 연결된 통합만 호출합니다. 지침은 브랜드 프로필 및 기타 활성 기술과 함께 컨시어지의 전반적인 런타임 동작으로 구성됩니다.

기술은 무엇을 언제 할 것인가를 결정한다. 그 자체가 어떤 데이터에도 연결되지 않습니다. 즉, 통합의 역할입니다.

## 통합

통합은 컨시어지의 기능 계층입니다. 데이터를 실제로 가져오거나 작업을 수행하는 외부 또는 백엔드 시스템(기술 자료, 콘텐츠 소스, 라이브 상거래 카탈로그)에 대한 연결입니다. 스킬이 판단인 경우 통합은 역량입니다.

모든 통합에는 다음과 같은 특성이 있습니다.

| 특성 | 의미 |
| --- | --- |
| 연결 및 자격 증명 | 통합은 상거래 환경 ID 및 API 키와 같은 자체 구성을 사용하여 백엔드를 인증합니다. 이 구성은 올바른 데이터 소스를 가리키는 요소입니다 |
| 노출된 기능 | 통합은 하나 이상의 호출 가능한 기능을 사용할 수 있도록 하며, 스킬이 호출할 수 있는 개별 작업입니다. 예를 들어 Commerce MCP는 제품 검색, 제품 세부 사항, 변형 및 Facet 검색을 별도의 기능으로 노출합니다 |
| 재사용 가능 | 하나의 통합이 여러 스킬에 연결될 수 있으며, 동일한 통합이 여러 컨시어지 및 고객에게 제공됩니다. 이러한 재사용은 프레임워크의 핵심 효율성입니다 |

런타임 시 통합이 작동하는 방식: 스킬이 실행되고 데이터가 필요하다고 판단되면 통합의 도구 중 하나를 호출합니다. 통합은 라이브 백엔드에 대해 해당 호출을 실행하고 구조화된 데이터를 스킬에 반환하며, 스킬은 이를 사용하여 응답을 구성합니다.

통합은 기능을 제공하지만 판단력은 행사하지 않습니다. 스킬에 의해 호출될 때까지 기다린 후 특정 작업이 요청되었는지 확인하고 결과를 반환합니다.

### 기능 및 제한 사항(셀프 서비스 경계)

- **셀프 서비스, 엔지니어링 없음:** 지침을 편집하고, &quot;사용 시기&quot; 트리거를 편집하고, 기존 통합을 연결하거나 분리하고, 기술을 활성화하거나 비활성화하고, 지원되는 통합(예: 유효한 자격 증명이 있는 Commerce MCP)에 연결합니다.

- **셀프 서비스가 아님, 엔지니어링이 필요함:** 카탈로그에 아직 존재하지 않는 새로운 도구 또는 커넥터를 만들거나, 프레임워크에서 지원하지 않는 새 보호 범주를 추가하거나, 백엔드에서 표시하는 데이터를 변경합니다.

- **두 스킬 간의 겹침 트리거는 구성 위험입니다.** 두 스킬이 동일한 메시지에서 발생할 수 있는 경우 라우팅이 일치하지 않을 수 있습니다. 라우터에 의존하여 해결하지 않고 트리거를 작성하여 진정한 모호성을 방지하십시오.

## FAQ

**스킬과 통합의 차이점은 무엇입니까?**

통합은 데이터 소스 또는 백엔드에 대한 연결입니다. 컨시어지가 연락할 수 있는 대상입니다(예: 기술 자료 또는 라이브 상거래 카탈로그). 스킬은 비헤이비어로, 컨시어지가 무엇을 하는지, 언제 하는지, 어떤 통합을 사용할 수 있는지를 결정합니다.

**경험에 따른 규칙:** 통합은 기능입니다. 스킬은 해당 기능의 사용 시기 및 방법에 대한 판단입니다.

**둘 이상의 스킬에서 동일한 통합을 사용할 수 있습니까?**

네, 그리고 이것은 의도적인 것입니다. Commerce MCP의 도구는 카탈로그 검색 및 제품 비교에서 공유됩니다. 통합을 한 번 빌드하고 많은 기술 및 많은 고객에서 재사용하는 것이 2.0 프레임워크의 핵심 효율성입니다. 이는 고객별 맞춤형 빌드를 제거하는 것입니다.

**전문가가 엔지니어링 없이 완전히 새로운 기능을 추가할 수 있습니까?**

카탈로그에 해당 통합이 이미 존재하는 경우에만 해당됩니다. 전문가는 기존의 모든 통합을 자유롭게 매핑, 구성 및 지시할 수 있습니다. 즉, 셀프 서비스입니다. 그러나 기능에 아직 존재하지 않는 백엔드 또는 커넥터(새 API 또는 새 데이터 소스 유형)가 필요한 경우, 이는 먼저 통합을 빌드하는 엔지니어링 작업입니다. 카탈로그에 존재하게 되면 이를 구성하는 것이 다시 셀프 서비스가 됩니다.

**BC 1.0의 단일 시스템 프롬프트와 어떻게 다릅니까?**

1.0에서 동작은 안전하게 편집하기 어렵고 일반적으로 엔지니어링을 변경해야 하는 하나의 큰 시스템 프롬프트(매니페스트)에 의해 제어되었습니다. 2.0에서 매니페스트는 여전히 존재하지만 하나의 블록으로 작성되지 않고 모듈식 조각으로 구성됩니다. 이것이 바로 전문가가 동작을 구성할 수 있게 하고, 하나의 프롬프트에 매몰되는 대신 개별 보호 기능 및 지침을 읽기 가능하고 감사 가능하도록 하는 것입니다.

**초기 크롤링은 정확히 무엇을 만드는가?**

사이트 검색은 사이트 맵을 통해 10페이지에서 15페이지까지 작성된 지식 기반을 생성합니다. 데이터 계층만 해당됩니다. 크롤링은 스킬이나 통합을 생성하지 않으며 나중에 작동합니다.

**크롤링에서 기술 자료를 만드는 경우 기술 자료 검색 통합은 무엇입니까?**

기술 자료 검색은 해당 기술 자료를 검색하는 작업이 포함된 기본 제공 통합입니다. 기술 자료 는 데이터이고, 기술 자료 검색 은 이를 쿼리하는 기능입니다. 이는 두 가지 별개의 문제입니다. 하나는 콘텐츠이고, 다른 하나는 콘텐츠를 읽는 도구입니다. 그들을 같은 것으로 취급하는 것은 흔한 실수이다. 그들은 그렇지 않다.

**컨시어지가 처음부터 끝까지 일반적인 질문에 어떻게 답합니까?**

세 개의 레이어가 순서대로 작동하며 스킬, 통합 및 데이터 모델에 정확하게 매핑됩니다.

- 초기 크롤링은 (데이터) 페이지에서 지식 기반을 생성합니다.
- 기본 제공 기술 자료 검색 통합은 해당 기술 자료(통합)를 검색합니다.
- 사이트 자문 기술은 기술 자료 검색(비헤이비어)을 호출하도록 연결되어 있습니다.
