# Brand Concierge에 대한 지식 소스 만들기 및 관리

지식 소스는 방문자 질문에 답변할 때 컨시어지가 사용할 수 있는 콘텐츠입니다. 모든 컨시어지에는 구성된 지식 소스가 하나 이상 필요합니다. 지식 소스는 독립적으로 생성되며 여러 컨텍스트에서 재사용할 수 있습니다.

컨시어지는 구성된 지식 소스만 사용하여 질문에 답변합니다. 그것은 일반적인 세계 지식으로부터 답하지 않는다.

>[!NOTE]
>
>방문자가 구성된 지식 소스 외부의 정보에 대해 질문하면 지원되지 않는 답변을 생성하는 대신 정보가 없음을 나타내도록 콘시어지가 설계되었습니다. 이 동작을 확인하려면 평가 프로세스를 사용하십시오.

## 기술 자료 원본 선택

| 기술 자료 출처 | 다음의 경우에 사용 | 주요 기능 |
| --- | --- | --- |
| AEM Sites (Content AI index) | 고객은 콘텐츠 AI가 활성화된 AEM Sites as a Cloud Service을 사용합니다. | 기존 콘텐츠 AI 인덱스를 사용하고 별도의 크롤링 또는 새로 고침 단계 없이 업데이트된 AEM Sites 콘텐츠를 사용할 수 있도록 합니다. |
| 웹 사이트 링크 | 고객은 플랫폼 구축에 사용되는 것과 관계없이 크롤링 웹 사이트를 필요로 합니다. | 개별 URL 또는 선택한 CSV 파일. |
| 제품 카탈로그 | 고객은 제품 또는 서비스 카탈로그가 비교적 작으며 Adobe Commerce을 사용하지 않습니다. | 컨시어지 응답에서 제품 딥링크 및 제품 카드를 사용할 수 있습니다. |

>[!IMPORTANT]
>
>소스 자료는 대형 카탈로그와 함께 Adobe Commerce을 통해 판매하는 고객은 대신 Commerce MCP 통합을 사용해야 한다는 점을 언급하고 있습니다. 해당 통합에 대한 자세한 내용은 이 문서의 범위를 벗어납니다.

## AEM Sites 지식 소스 만들기

고객이 이미 컨텐츠 AI가 활성화된 AEM Sites as a Cloud Service을 사용하고 있는 경우 AEM Sites 지식 소스를 사용하십시오.

1. **기술 자료 Source 빌드**&#x200B;를 선택합니다.
1. **AEM Sites**&#x200B;를 선택하고 **계속**&#x200B;을 선택합니다.
1. 기술 자료 출처의 이름과 설명을 입력합니다. 예를 들어 `My main website`을(를) 이름으로 사용합니다.
1. 목록에서 기존 Content AI 인덱스를 선택합니다. 이 목록은 AEM Sites as a Cloud Service 인스턴스에서 채워집니다.
1. **저장**&#x200B;을 선택합니다.

이 기본 통합을 통해 업데이트된 AEM Sites 컨텐츠를 Brand Concierge에서 자동으로 사용할 수 있습니다. 별도의 새로 고침 단계가 필요하지 않습니다.

## 웹 사이트 링크 기술 자료 소스 만들기

크롤링 가능한 웹 사이트에 대한 Website Links 지식 소스를 사용합니다. 이 옵션은 모든 플랫폼에 구축된 웹 사이트에 대해 작동하며 대부분의 처음 사용하는 사용자에게 권장되는 옵션입니다.

1. **기술 자료 Source 빌드**&#x200B;를 선택합니다.
1. **웹 사이트 링크**&#x200B;를 선택하고 **계속**&#x200B;을 선택합니다.
1. 기술 자료 출처의 이름을 입력합니다.
1. 다음 방법 중 하나를 사용하여 콘텐츠 소스를 추가합니다.

   - **사이트 맵 URL:** 사이트 페이지를 나열하는 URL을 하나 추가합니다. 사이트 맵에는 모든 페이지가 나열되어 있습니다.
   - **개별 URL:** 특정 페이지 URL을 한 번에 하나씩 추가합니다. 추가된 페이지만 크롤링.
   - **CSV 업로드:** 샘플 파일을 다운로드하고 URL을 추가한 다음 완료된 CSV 파일을 업로드합니다.

1. (선택 사항) 지정된 날짜 및 시간의 주별 등 새로 고침 빈도를 예약하여 웹 사이트가 변경될 때 지식 소스를 최신 상태로 유지합니다.
1. **추가** 또는 **만들기**&#x200B;를 선택합니다.

지정된 URL을 빌드하고 콘텐츠를 스크랩하는 시스템 크롤링.

>[!TIP]
>
>사이트 맵은 일반적으로 `yourwebsite.com/sitemap.xml`에서 사용할 수 있습니다. 웹 사이트에서 사이트 맵을 제공하지 않는 경우 대신 개별 페이지 URL을 추가합니다.

## 제품 카탈로그 기술 자료 원본 만들기

Adobe Commerce을 사용하지 않는 소규모 제품 또는 서비스(약 100개 미만)의 고객을 위해 제품 카탈로그 지식 소스를 사용하십시오.

컨시어지 응답이 제품을 참조할 때 제품 카탈로그는 제품 페이지에 대한 딥 링크를 제공하고 제품 카드를 활성화할 수 있습니다. 제품 카드에는 이미지, 제목, 설명 및 하나 또는 두 개의 버튼이 포함될 수 있습니다.

1. **기술 자료 Source 빌드**&#x200B;를 선택합니다.
1. **제품 카탈로그**&#x200B;를 선택하고 **계속**&#x200B;을 선택하세요.
1. 기술 자료 출처의 이름을 입력합니다. 예를 들어 `My product catalog - US region`을(를) 이름으로 사용합니다.
1. 스키마를 선택합니다. 스키마는 표시되는 제품 필드(예: 이미지, 제목, 설명, 단추)와 단추 링크를 정의합니다.
1. 선택한 스키마에 대한 샘플 스프레드시트를 다운로드합니다.
1. 제품 데이터를 스프레드시트에 추가하고 업로드합니다.
1. **저장**&#x200B;을 선택합니다.

버튼 구성마다 다른 스키마가 필요합니다.

## 기술 자료 원본 상태 모니터링

각 지식 소스에는 처리 상태가 표시됩니다.

| 상태 | 의미 |
| --- | --- |
| 진행 중 | 지식 소스가 현재 처리 중입니다. |
| 성공 | 지식 소스는 완전히 처리되어 사용할 준비가 되었습니다. |
| 예약됨 | 기술 자료 출처는 향후 예정된 시간에 처리됩니다. |
| 부분적인 성공 | 일부 페이지는 성공적으로 처리되었지만 다른 페이지는 실패했습니다. |

기술 자료 소스 세부 정보 페이지는 다음과 같은 정보를 제공합니다.

- 제작자.
- 만든 날짜입니다.
- 제공된 링크 또는 페이지 수입니다.
- 성공 또는 실패한 링크 또는 페이지 수입니다.
- 마지막 새로 고침 시간.
- 처리에 고려되는 URL입니다.

## 처리 실패 문제 해결

지식 소스가 부분 성공 상태를 표시하는 경우 문제 보고서를 사용하여 처리할 수 없는 URL을 식별합니다.

1. 기술 자료 출처 세부 정보 페이지를 엽니다.
1. **문제 해결**&#x200B;을(를) 선택하여 오류 세부 정보와 함께 손상되었거나 스크랩할 수 없는 URL이 포함된 파일을 다운로드합니다.
1. 잘못된 URL을 수정하거나 소스 목록에서 제거하십시오.
1. 해당되는 경우 수정된 URL 목록을 다시 업로드합니다.
1. 수정된 콘텐츠가 지식 소스에 추가되도록 재처리를 요청합니다.
